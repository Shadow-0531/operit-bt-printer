# 教程：从零把 PD01 热敏打印机接到 Operit

> 这份教程记录了一个真实踩坑过程：在 Operit 中用 ToolPkg 插件控制 BLE 热敏打印机。
> 核心难点是绕过 Java Bridge 的一个回调限制，最后用 `loadDex` 自编 Java 类解决。

---

## 第一步：先认清卡在哪

直接调：

```js
var cb = Java.implement("android.bluetooth.BluetoothGattCallback", {
  onConnectionStateChange: function(gatt, status, newState) { ... }
});
device.connectGatt(ctx, false, cb);
```

会报：`no method matched`。

原因：Operit 的 Java Bridge 在“参数类型重载匹配”时，认不出 JS 侧的 interface marker。

**试过但走不通的路：**
- 反射 `Class.forName(...)`：只返回字符串，拿不到 Class 对象。
- `getClass()`：同样只返回字符串。
- `new Java.type(...)(obj)` / `newInstance(obj)` / ArrayList 中转：都不行。

一个有用的线索：把 marker 塞进 ArrayList 再取出来，它的真实类型是 `JsJavaBridgeDelegates$JsInterfaceBinding`——说明对象是真实的，但重载匹配器不认。

## 第二步：换思路——自编 Java 类

既然桥过不去，那就**把连蓝牙的逻辑写成一个真正的 Java 类**，编译成 dex，运行时加载：

```js
Java.loadDex("/path/to/btbridge.dex");
var st = Java.callStatic("com.shadow.bt.BtBridge", "connect", ctx, mac);
```

Java 内部直接写 `device.connectGatt(ctx, false, this)`——**这是编译期静态调用，根本不经过桥的重载匹配器。**

问题解决。

## 第三步：搭 dex 编译链（难在工具链）

```bash
# JDK
apt install default-jdk-headless

# d8：Debian 的 build-tools 不带 d8，从 google maven 拿 r8.jar
curl -sL -o /tmp/r8.jar \
  https://maven.google.com/com/android/tools/r8/8.3.37/r8-8.3.37.jar

# android.jar
curl -sL -o /tmp/android.jar \
  https://raw.githubusercontent.com/Sable/android-platforms/master/android-34/android.jar

# 编译
javac -source 8 -target 8 -bootclasspath /tmp/android.jar \
  -d out src/com/shadow/bt/BtBridge.java

# 转 dex（注意：输出目录必须先存在）
mkdir -p dexout
java -cp /tmp/r8.jar com.android.tools.r8.D8 --min-api 24 \
  --output dexout out/com/shadow/bt/*.class
```

产出的 `classes.dex` 放进插件的 `dex/` 目录。

## 第四步：协议对接

协议细节看 `PROTOCOL.md`。**第一个大坑是 CRC8**：

- 一开始以为要算整包，结果设备“能连上但只发回流控、不出纸”。
- 查协议实现后发现 **CRC8 只覆盖 DATA 段**。改对之后就通了。

## 第五步：文字怎么变成纸上的字

热敏机不认识“文字”，只认点阵。所以要：

1. 用 PIL 把文字画成 **384 像素宽** 的图；
2. 转 1-bit 黑白；
3. 每行 48 字节，按 **LSB-first** 拼成位图数据；
4. 逐行用 `0xA2` 包发出去。

`tools/render.py` 就是这个事。

## 第六步：让内容可换（不用重打包）

把位图文件路径做成 **运行时读取**，而不是编译进代码。
于是改一个文本文件 -> 重新渲染 -> 直接调工具打印，全程不用重新打包和解装插件。

## 第七步：装插件

- 在 Operit UI 里用「➕ 导入 .toolpkg」。
- **不要手改 cache 目录**，否则会被判包损坏并清掉配置。

## 总结：绕桥的三个关键词

1. **loadDex** —— 自编 Java 类，避开桥的回调限制。
2. **CRC8 只算数据段** —— 协议最容易错的地方。
3. **运行时读文件** —— 让内容可换、不用重打包。
