# PD01 协议速查

> 适用于 PD01 系热敏打印机（猫机 / 喵喵机 / Paperang 系）。

## 1. 包格式

```
[0x51][0x78][CMD][0x00][LEN_LO][LEN_HI][DATA...][CRC8][0xFF]
```

| 字段 | 长度 | 说明 |
|---|---|---|
| 0x51 0x78 | 2 | 固定包头 |
| CMD | 1 | 命令码 |
| 0x00 | 1 | 固定保留字节 |
| LEN | 2 | DATA 长度（小端） |
| DATA | N | 数据 |
| CRC8 | 1 | **只算 DATA 段**，多项式 0x07，初值 0x00 |
| 0xFF | 1 | 固定包尾 |

> ⚠️ **最容易错的地方：CRC8 只覆盖 DATA，不包含 CMD / 长度 / 包头。**
> 算错了会表现为“能连上、能写、但设备不响应”。

## 2. GATT 服务与特征

| UUID | 用途 |
|---|---|
| `0000ae30-0000-1000-8000-00805f9b34fb` | 主服务 |
| `0000ae01-...` | 写特征（WriteNoResponse） |
| `0000ae02-...` | 通知特征（Notify，需写 CCCD 2902 开启） |

## 3. 常用命令

| CMD | 作用 | DATA 样例 |
|---|---|---|
| `0xA2` | 位图行（每行 48 字节 = 384 像素） | 视位图而定 |
| `0xA2` | 设置打印质量 | `31`~`35` 对应 1~5 |
| `0xA1` | 走纸 | `30 00` = 48 步 |
| `0xA6` | lattice 初始化 / 结束 | init: `AA 55 17 38 44 5F 5F 5F 44 38 2C` |
| `0xA3` | 查询状态 | `00` |
| `0xAE` | 流控应答（设备主动回，非请求） | — |

## 4. 官方包样例（实测可用）

```
走纸   5178 A1 00 0200 3000 ?? FF
查状态 5178 A3 00 0100 00 ?? FF
init   5178 A6 00 0B00 AA551738445F5F5F44382C ?? FF
```

## 5. 设备应答格式

```
[0x51][0x78][CMD][0x01][LEN][DATA][CRC8][0xFF]
```

与请求的唯一区别：**第 4 字节固定为 `0x01`**（请求恒为 `0x00`）。

实测示例（查状态应答）：`51 78 A3 01 03 00 00 00 73 5E FF`，其中 data = `00 00 00` 表示状态正常。

## 6. 位图格式

- 宽：**384 像素**（48 字节 / 行）
- 每字节 8 像素，**位序 LSB-first**
- 1 = 打黑点，0 = 留白
- 逐行发送：每行一个 `0xA2` 包

## 7. 打印流程顺序

```
连接 -> 开通知(0xAE02 写 CCCD)
 -> 设置质量
 -> lattice 初始化
 -> 逐行发送 0xA2 位图（建议每行间隔 10~12ms）
 -> 走纸 0xA1
 -> lattice 结束
 -> 查询状态 0xA3
```

## 附录：CRC8 参考实现

```python
def crc8(data: bytes) -> int:
    crc = 0x00
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = ((crc << 1) ^ 0x07) & 0xFF if crc & 0x80 else (crc << 1) & 0xFF
    return crc & 0xFF
```
